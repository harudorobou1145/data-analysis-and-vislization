# 第一阶段实验设计
研究对象：同一固定 Codex 模型在 low/medium/high 下的任务表现。RQ1 成功率；RQ2 耗时/Token；RQ3 任务类型的差异；RQ4 工具、测试及错误修复行为；RQ5 质量收益与资源代价。均为待验证问题。

固定模型名称与 CLI 版本、任务文本、初始文件、工具权限、Python/测试、验收标准。每次 `codex exec` 全新会话，无 resume，独立 UUID 工作区。记录 prompt 与初始代码 SHA256。模型别名不保证后台版本固定：正式采集前确认快照可用性，记录采集日期和模型缓存，若无法钉住后台版本则明确局限。温度/系统提示/服务端版本未提供则记未知，不能假定相同。

T001 是简单调试试验：空列表返回 0，正常/负数/浮点数正确；验收预先固定 5 个 pytest 参数案例。只复制 starter，prompt 为公开规范，不把隐藏验收复制进去。T001 不作研究结论。后续扩充算法、调试、数据处理及难度，按任务×强度平衡重复，随机/轮换运行顺序并保留种子和计划表；不预设高强度更好。

## 隔离边界与暂停条件
`workspace-write` 限制写入，不保证不能读取项目外的隐藏测试；当前 Windows 子进程也不提供可靠 CPU/内存/网络/文件读取隔离。**本机未验证可靠隔离，真实模型和生成代码验收本阶段均不运行。**
正式执行前应在 Windows Sandbox/专用虚拟机/受控容器中验证：智能体只挂载该 run 的 starter 工作区，隐藏验收和其他实验目录不可读；不挂载宿主盘/个人目录；限制 CPU、内存、磁盘、进程数和网络。模型阶段只允许必要服务网络；验收阶段禁网、最少权限、无凭据，仅挂载冻结后的候选代码及可信测试。不能仅在宿主机加一个参数就认为完成隔离。
`--isolation-confirmed` 是人工确认声明，不是自动创建沙箱。验收默认 blocked_isolation；`--allow-host-evaluation` 意味着用户另行明确同意当前环境执行生成代码，优先只在上述受控来宾环境中开启。评估器提供进程超时和凭据环境变量过滤，但不是安全边界，也没有实现 CPU/内存硬配额；恶意子进程可能存活。测试启动后把隐藏测试加载进进程，无法对恶意候选代码保密。正式研究还需防测试篡改/检测，人工审查候选差异。

CLI 使用 `--ignore-user-config` 避免个人 hooks/MCP 配置漂移，但当前提供方为 openai-http，此参数可能导致提供方切换或认证失败。获准后需在安全环境核对默认官方提供方，若需要自定义提供方，先审核并制作最小固定 profile，再统一修改调度命令；不直接继承未审查个人配置。不得添加绕过沙箱选项。

## 判定与时间
execution_status 只表示 CLI 进程状态；agent_completed 表示观察到 turn.completed 且无错误；task_success 主要由独立验收（全部测试通过且用例数>0）决定。CLI 失败但代码通过可同时记录，不互相覆盖。缺失验收用 null，不假定失败/成功。失败、超时、认证错误均保留原始日志，不悄悄重试；新重跑必须新 run_id。
duration_seconds 为 CLI 启动到退出的墙钟时间，不含独立验收；时间戳 UTC。arrival_times 是采集器收到日志行的时间，受缓冲影响，并非模型内部行为时刻。没有真实事件时间就保持空或明确为接收时间。
