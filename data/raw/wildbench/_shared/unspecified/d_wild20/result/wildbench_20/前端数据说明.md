**WildBench 20题实验：前端数据说明**

同一20题，比较 Sol low、Sol high、Sol ultra、Luna high 四组配置，涉及两个模型。每题每组独立回答2次，每组40份，共160份。主评160份，另抽16份重复盲评，每组4份。独立任务样本量为20题。

优先读取结果目录 `result/wildbench_20/` 内的文件：

| 文件 | 用途 |
|---|---|
| `frontend_rows.jsonl` | 推荐明细入口，每行一份计划回答，含正文、主评分、耗时、tokens |
| `merged_results.json` | 明细在 `rows`，重复盲评在 `repeat_scores` |
| `summary.json` | 分组、配对和复评统计；正式展示需 `status = complete_audited` |
| `frontend_metrics.csv` | ID、状态和数值指标，无回答正文；缺失留空 |
| `重试开销.json`、`重试开销说明.md` | 失败及重试开销；裁判开销单列 |
| `audit.json` | 正式展示前确认 `status = passed`、`require_complete = true`、`issues = []` |

主连接键为 `experiment_id + run_id`，现成行ID为 `record_id = experiment_id::run_id`。`task_id` 表示题目，`condition_id` 表示配置，`repeat_id` 表示第1或第2次回答。评分通过 `answer_request_id`、`answer_attempt_id`、`answer_hash` 关联原回答。`judge_request_id` 属于裁判请求。

质量图表只使用 `row_status = completed` 且 `join_issues = []` 的行。`answer_status`、`score_status` 分别为回答和主评状态。进度数据含未完成行，各组完成题目可能不同，不能提前排名。

`score_10` 是1至10整数质量分，不能标为“正确率”。`wb_score = (score_10 - 5) × 2`，范围为−8至10。总体均分先平均同一题同一组的2份回答，再对20题平均；配对比较使用这20个题目均分。满分率按每组40份回答计数。

`elapsed_seconds` 为被选中成功请求的运行时turn时长，包含思考及服务、网络等待；`client_elapsed_seconds` 为客户端等待，`wall_seconds` 另含准备和清理。主表时延仅覆盖每组40次成功请求，600秒超时等失败等待见重试文件，评估效率需同时查看。重试文件累加各次wall，并发时间有重叠，累计值不能解释为整批实际历时。

`client_first_answer_delta_seconds` 应标为“首段可见文本等待”。`ttft_seconds`、`tpot_seconds` 的 `null` 表示缺失，禁止补0，也不可用可见文本等待代替真实TTFT。

`token_usage` 内有 `inputTokens`、`outputTokens`、`reasoningOutputTokens`、`totalTokens` 等。候选与裁判用量分开，缺失保留；已知token合计无法代表完整账单。

每组仅4份复评回答，可能来自同一题。复评差异只描述这些回答的裁判波动，不能证明裁判准确或公平。20题结果适合探索，单一裁判可能受模型家族、风格和长度影响。

本轮题集和评分规则均与上一轮通用四维评分不同，分数不可直接比较或合并，下降不能单独归因于难度。图表标注“WildBench v2-hard 20题子集”，避免标为官方完整排行榜成绩。
