# TOP Bench 提示词实验的数据接入与可视化方案

本次只接入新完成的 TOP-Bench v3 实验：固定中转站 `gpt-6.1-sol`、High，20道同题分别运行原始提示、TNM、CBD，共60组。既有数据集和两个比较方向继续使用原来的页面与数据，不在本次改动范围。

扩展更新：现已追加60道不重复的新题，并与原20题统一为80题、240组结果，移除批次切换。每领域16题、每档难度20题、每交叉单元4题；所有视图和CSV均在合并题集上筛选、联动。下文20题成绩保留为首批记录，合并成绩与复现步骤见《TOPBench新增60题结果.md》。底层来源标识仅用于追溯。

核心分析问题是：**隐私保护提示是否减少敏感信息泄漏？它是否同时损失了任务完成度？同一道题中的工具选择发生了什么变化？**

## 数据已经准备到什么程度

原始证据在 `data/raw/topbench3/topbench3_sol_high_prompts20_v1/`，只供团队内部追溯。原始工具返回和目标敏感结论不直接用于公开展示。

现有结构化结果在 `data/processed/topbench3/topbench3_sol_high_prompts20_v1/`。本次增加其下的 `visualization/`：

| 文件 | 用途 |
| --- | --- |
| `dashboard_data.json` | 给未来TOP-Bench页面使用的指标白名单数据，包含汇总、分组、60条结果、20个题目、240次请求的时间记录、工具选择关系 |
| `quality_report.json` | 样本完整性、唯一性、缺失字段和评分局限 |
| `manifest.json` | 上游数据和本次输出的SHA256，用于核查来源 |
| `README.md` | 字段含义、统计口径和数据接入方法 |

数据生成脚本是 `app/experiments/topbench3/prepare_visualization.py`。仅使用Python标准库、离线运行，不调用模型，不修改前端。页面实现位于 `app/dashboard/src/TopBenchPage.tsx`，只接入本批TOP-Bench数据。

这次处理检查了运行与题目标识是否重复、三策略是否配对完整、评分标签是否为真实布尔值、四类结果是否一致、选择工具是否与图节点一致，并将请求级Token与运行级Token逐一核对。原始时间统一为UTC，展示时再转换为用户时区。缺失值保留null，不补成零。

## 与现有页面的关系

当前 `app/dashboard/src/App.tsx` 的主导航按“思考深度”和“不同模型”组织，两个方向下有数据集详情。TOP-Bench这批数据固定模型和推理强度，比较变量是提示词策略。

建议在同一层新增 **提示词策略 → TOP-Bench v3**。进入后继续复用现有Material UI主题、卡片、筛选器、图表放大、CSV导出和右侧抽屉。当前两个方向和原有图表无需为此重构。

实现后，`export-data.mjs`会调用独立的 `export-topbench.mjs`，把经校验的展示包输出到 `public/topbench-data.json`。新页面以 `#mode=prompts&dataset=topbench3` 路由独立加载；旧 `Row` 类型和原有1845条候选指标不变，60条策略记录不混入Low/High/Ultra或多模型分组。

## 三个核心联动视图

### 同题结果矩阵

行是TOP001至TOP020，列是原始提示、TNM和CBD。单元格使用四种离散状态：

| 状态 | 建议编码 |
| --- | --- |
| 完成且安全 | 深绿色，实心圆 |
| 完成但泄漏 | 橙色，警示标记 |
| 未完成但安全 | 蓝灰色，空心圆 |
| 未完成且泄漏 | 暗红色，叉号 |
| 评分未知 | 灰色斜纹，不能与安全混淆 |

行旁显示领域、难度；支持按题号、领域或策略间结果分歧排序。默认保留全部20题。鼠标悬停显示三种策略的完成判定、泄漏判定、所选工具数和作答Token。

点击一行，下方工具图同时显示该题的三种策略；框选多行，则右侧散点及顶部指标只在这些共同题目上重算。筛选始终以题目为单位，三策略一起进入或退出，避免分母不一致。

现有ALFWorld环形热图说明项目已具备同题多条件比较能力。这一页用矩形矩阵更容易同时读取20题的四种状态，视觉语言仍可沿用现有主题。

### 完成率与泄漏率散点

横轴是泄漏率LR，越低越好；纵轴是完成率CR，越高越好。原始提示、TNM、CBD各一个点，左上区域表示完成度高且泄漏低。

默认使用等大点。允许切换为以平均作答Token编码圆面积，并展示明确的大小图例。H分数和“完成且安全比例”放在悬停信息中，不另造第三个空间轴。

领域和难度筛选、矩阵框选都会更新三个点及N值，使用约200毫秒的坐标过渡。悬停某策略时，高亮矩阵对应列；点击策略时突出该策略的工具选择关系。

这一张图同时解释策略、完成率、泄漏率，能比三个独立柱状图更直接地表达权衡。当前只有三个总览点，必须配合矩阵和分组筛选，不能单独作为整页。

### 工具选择对照图

选中一题后，左侧放三个策略节点，右侧放该题可用的匿名工具节点；工具按 `tool_family` 排列。连线表示某策略选择了该工具，未选择节点保留淡色。点击工具，高亮哪些策略选择了它，以及相应结果。

参考隐私支撑集合成员用虚线外框标记，图例注明其含义。它是数据集标注的隐私推断支撑集合，不等同于完成用户任务的最优工具集合。

工具图展示的是**选择关系**。本实验使用固定JSON工具返回，没有真实外部工具执行，也没有可观测的模型内部推理链。不能把这些边标成模型“实际推理路径”，或把 `tool_call_count` 解释成真实API/MCP调用次数。

详情抽屉展示题号、领域、难度、三策略结果、工具家族、作答与评分Token、四阶段请求时间。公开页面不直接放原始回答、工具返回和目标敏感结论；若需要文本案例，另行人工匿名化并审核。

## 可增加的两种展示效果

### 配对结果变迁桑基图

提供两个比较开关：原始提示→TNM、原始提示→CBD。左右各有四类结果节点，连线宽度表示有多少道同题从基准状态变成另一策略下的状态。

点击“完成但泄漏→未完成但安全”这类连线，矩阵只高亮对应题目，工具图显示其中一题。连线代表独立实验之间的同题配对，不代表一次对话里按顺序修改策略。

该图最适合解释“减少泄漏的同时发生了哪些任务结果变化”。数据已准备在 `paired_outcome_changes`，不需要额外跑模型。

### 四阶段请求时间线

针对选中题目，用三个策略泳道显示：选工具、生成回答、完成度评分、泄漏评分。作答与评分阶段用不同底色或明确分区，切换显示持续时间或Token。

所有240次HTTP请求均有阶段记录。时间线展示实际请求次序与耗时；模型作答耗时与评分开销分开统计。它不表示真实工具动作轨迹，也不表示多角色对话。

## 这批结果适合讲什么故事

以下结果都来自20道完整配对题，不扩展为1000题总体结论。

| 策略 | CR完成率 | LR泄漏率 | H | 完成且安全比例 | 平均选中工具数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始提示 | 60% | 40% | 0.600 | 40% | 2.95 |
| TNM | 45% | 25% | 0.563 | 35% | 2.45 |
| CBD | 40% | 40% | 0.480 | 20% | 2.50 |

适合以“更谨慎是否也更有用”为叙事主线：

1. TNM的总体泄漏率下降15个百分点，同时完成率也下降15个百分点。
2. TNM平均选中工具数较少，但这是观测关联。需要通过同题矩阵和工具对照，进一步定位哪些题出现这种组合。
3. CBD本次没有降低总体泄漏率，且完成率较低，可通过桑基连线定位其退化题目。
4. H与“完成且安全比例”含义不同，保留两者能防止只用一个分数掩盖具体结果。

领域每组只有4题、难度每组只有5题，领域×难度每格只有1题。热图与筛选可以帮助找案例，不能据此声称某领域存在稳定的总体规律。自动评分使用与作答相同的模型、独立盲化上下文；12份待人工复核材料已在原始证据的 `human_review/` 中准备好，尚不能当作人工真值。

## 技术实现与验收

现有ECharts已能完成散点、热图、桑基和图关系；时间线可用ECharts custom series或SVG。先复用现有图表组件和抽屉，不需要为这60条记录增加后端或新的数据库。

后续实现时统一维护 `selectedTaskIds`、`selectedStrategy`、领域和难度四类状态。点击和框选改变选中集合，悬停只高亮，重置恢复完整20题。任何汇总先取三策略评分完整的共同题目，再重新计算CR、LR及H，不能平均单题H。

优先级：先完成矩阵、权衡散点、工具对照三视图及联动，再增加桑基和时间线。视觉细节采用现有主题、稳定颜色、清晰图例、轻量过渡和选中高亮。题目明确要求不使用无实际意义的3D图，这一页用配对联动和可追溯案例体现交互深度。

验收时至少检查：

- 默认显示20题、60条结果，三策略分母均为20，汇总与上表一致。
- 框选3题时三个策略均按这3题计算，重置能恢复20题。
- 点击矩阵行能切换同题工具关系和请求时间线，悬停策略能跨图高亮。
- 工具图不输出工具返回或敏感结论，详情不暴露原始回答与凭据。
- 导出只导出当前选中的匿名指标，并记录策略、领域、难度和分母。
- 旧两个研究方向及原有数据保持原来的运行行为。

## 复现命令

在仓库根目录使用Python 3.10及以上版本：

```powershell
python app/experiments/topbench3/prepare_visualization.py
```

此命令只构建本批数据的展示包和质量报告，不会触发新实验。随后在 `app/dashboard/` 执行 `npm run dev`，点击侧栏“提示词策略”即可查看实现。`npm test`覆盖配对分母、未知判定、空选择、H公式、桑基配对与隐私字段导出边界。
